# 为什么需要 eval-gate

## 一个常见的场景

同一个模型、同一批 480 道题，只换了一次抽样。第一次跑出 80.6%，第二次跑出 80.2%。两次评测的负责人得出相反结论：一个人说“回退了，不能合”，另一个人说“在噪声内，可以合”。

真正的问题往往不在模型，而在**判决层**：拿一个点估计和一个手写阈值做比较，没有区间、没有配对、没有样本量约束。换一批题、换一个随机种子，结论就会横跳。

## 把三层拆开

| 层 | 负责什么 | 常见工具 |
|---|---|---|
| 执行层 | 把模型跑一遍，收集逐题输出 | promptfoo、DeepEval、Ragas、自建脚本 |
| 评分层 | 判断每道题过/不过 | rubric、LLM-as-judge、规则检查 |
| 判决层 | 这个差值是不是噪声？能不能放行？ | **缺失，通常是一行 `if score < 0.8: fail`** |

eval-gate 只补第三层。它读逐题结果，不调模型。

## 一个可以复跑的实验

`scripts/noise_demo.py` 从同一份 480 题、同一个 prompt 回退场景里，做 20 次 `n=40` 的子采样：

```bash
python3 scripts/noise_demo.py
```

真实输出（2026-11-04，bootstrap=2000，seed 固定）：

```
full n=480: verdict=BLOCK delta=-0.0729 delta_ci=[-0.0875, -0.0583]
gate-default n=40 x20: verdicts=['REVIEW'] flipped=False delta_range=[-0.1500, +0.0000]
forced-decide n=40 x20: verdicts=['BLOCK', 'FAIL'] flipped=True delta_range=[-0.1500, +0.0000]
```

三行说明三件事：

1. 全量 480 题时，delta 的 95% CI 是 `[-8.75pp, -5.83pp]`，整段都在 −3% 容差之外，`BLOCK` 是有依据的。
2. 只抽 40 题时，点估计在 `-15.00pp` 到 `+0.00pp` 之间跳。如果按点估计判决，20 次里会同时出现“显著回退”和“没有变化”。
3. 同一个 40 题数据，开启功效门禁（`n >= 400` 且 CI 宽度 ≤ 0.12）后，20 次全部是 `REVIEW`，一次都没有给出 `PASS/FAIL/BLOCK`。**它不是让结论更准，而是拒绝在没有证据时给结论。**

把功效门禁关掉（`min_n=40, max_ci_width=1.0`），同样的 20 次子采样立刻退化成 `BLOCK/FAIL` 混着出现。这就是“同一批题两次结论相反”的机制。

## 第二个断点：评分器被长度骗过

`p3_false_green` 里，候选答案统一变长、变空。一个“非空且长度 ≥ 20”的 naive 检查器给出 **100% 全绿**；同一个 rubric 的权威评分只有 **79.17%**，低于 80% 下限，判决 `FAIL`。

这说明判决层不能只看一个总分：要先确认评分器本身没有退化，再比较候选与基线。eval-gate 的归因表会同时打印两个通过率和落差（`+20.83%`），让“假绿”无法混进 PASS。

## 适用与不适用

适用：

- 你有逐题的 `pass/fail` 或 rubric 分数，候选和基线能按 id 配对。
- 你想在 CI 里阻断“显著回退”，但不想被抽样噪声反复误伤。
- 你需要一份能复算的证据，回答“为什么这次判 BLOCK”。

不适用：

- 你还没有评测集，或没有基线输出。先补执行层和评分层。
- 你需要 LLM-as-judge 生成分数。eval-gate 不做评分，只消费评分结果。
- 你的样本永远小于 400，且业务不接受 `REVIEW`。那就先在评测集扩容，或把 `min_n` 调到你的真实功效下限，并明确承担误判率。

## 它什么时候会错

判决层能拒绝无证据的结论，但不能代替你保证数据本身是对的。三类已知边界：

| 情况 | 后果 | 现有处理 |
|---|---|---|
| 标签本身有噪声 | 通过率整体偏移；配对后 delta 可能是 0，仍判 `PASS` | **未防护**，需人工抽检（FAILURE_MODES FM-02） |
| 基线来自旧版/更难的题集 | id 对得上但难度不同，delta 失真 | **未防护**，需冻结评测集（FM-04） |
| 判分器自身抖动 | 判分噪声进入 delta | **未防护**：G7 只标 `skipped`（FM-07） |

另外，统计近似本身也有误差（百分位 bootstrap 非 BCa、Wilson 非 Clopper-Pearson、未做聚类校正），
以及小样本下区间会宽到只能给出 `REVIEW`。这些写在
[STATS_DESIGN.md](../STATS_DESIGN.md) §7–§9；完整的 20 条失效模式与复现用例见
[FAILURE_MODES.md](../FAILURE_MODES.md)。

**能说清“我什么时候会错”的判决层，才值得接进流水线。** 如果上面任何一条正是你的场景，
先把那条缓解措施做掉，再读 `PASS`。

## 最小用法

```bash
python3 -m pip install .
eval-gate quickstart
```

4 个场景、4/4 判决、约 1–2 秒（本机实测 1.1–2.4s）。看完再决定要不要接进自己的评测流水线。
