# 用例 2：长度检查全绿，但评分器已经失效

**你会得到什么结论**：`FAIL`。候选答案只是变长、变空。一个“非空且长度 ≥ 20”的 naive 检查器给出 **100% 全绿**；同一个 rubric 的权威评分只有 **79.17%**，低于 80% 下限。

```bash
./run.sh
```

真实输出：

```
verdict=FAIL pass_rate=0.7917 ci=[0.7531, 0.8256] delta=+0.0000 delta_ci=[0.0000, 0.0000] n=480
exit=1
```

打开 `runs/false-green/attribution.md`，重点看这一行：

```
naive 检查器: 100.00% 全绿，与权威评分落差 +20.83%
```

这个用例回答的问题是：**为什么“评测全绿”不能直接当放行依据？** 因为评分器可能被表面特征骗过。判决层必须先确认评分器本身没有退化，再比较候选与基线。

数据为合成，但“答案变长骗过长度阈值”是 RAG / support QA 评测里最常见的假绿之一。
